How current state is established

Repository evidence, not README authority.

A stale README can understate a build; an aspirational README can overstate it. The commercial register therefore uses multiple first-party repository signals.

Source & structure

Implemented first-party modules, schemas, package boundaries, persistence, interfaces and operational surfaces are inspected where a head changed.

Execution evidence

Tests, retained reports, benchmark artifacts, exact-SHA validation, failure states and explicit NOT_EXECUTED markers determine how strongly a capability is credited.

Release & provenance

Version metadata, manifests, release binding, source/distribution hashes and reproducibility controls contribute to transfer-readiness analysis.

Risk boundaries

Blocked physical validation, pending GPU execution, synthetic-only evidence, missing external qualification and unresolved buyer deployment are retained as valuation constraints.
