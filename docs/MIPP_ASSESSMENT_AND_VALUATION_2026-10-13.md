# MIPP — source assessment and individual economic reference

Assessment date: **13 October 2026**. Asset: **TA-IP-106**. Project reference alias: **Euterpe**. Product: **Manuscript Integrity & Publishing Platform (MIPP)**. This is a separate software asset; author manuscripts, the creative archive and pseudonym rights do not become software rights by association.

## Existing product and assessed source

The frozen private repository baseline is `9b8b8d39cd86289fcd70c3684172a44062879bba`. The package manifest identifies application **v0.1.0**. All **52 repository blobs** were reconstructed and checked against Git's blob hashes. The current-source review passed **18/18 local Python tests**, the immutable UBQARP protocol check and Python syntax compilation. The package uses Python 3.10+ and the standard library; setuptools is a build dependency. These are local software results, not independent editorial, legal, scientific or security certification.

MIPP supports chapter writing and simple DOCX assembly, ordinary DOCX/Markdown/plain-text ingestion, an immutable UBQARP v1.0 foundation, eight gates and 40 ordered stages, SHA-256-bound evidence and manuscript fingerprints, S0–S3 defect rules, change-triggered invalidation, explicit owner authorization, a read-only localhost dashboard, and a manual Draft2Digital DOCX/metadata handoff. It does not log in to the distributor or publish a book.

The source `NOTICE.md` and `pyproject.toml` declare proprietary rights. The notice preserves separate ownership of the author-supplied protocol. A definitive transfer must identify the software deliverables and resolve embedded protocol/template permission. No source code or author content is disclosed by this public assessment.

Existing portfolio role budgets are retained: senior engineer **EUR 18,000/month**, lead/specialist **EUR 22,000/month**, and validation/provenance **EUR 16,000/month**. For the explicit sensitivity calculation, one role-month is assumed to contain **160 hours**, giving **EUR 112.50, EUR 137.50 and EUR 100/hour** respectively. 1. Direct budget: `2.25 × 18,000 + 0.50 × 22,000 + 0.75 × 16,000 = EUR 63,500`.
2. A separate **15% coordination/tooling allowance** adds **EUR 9,525**, giving **EUR 73,025**. It is an assumed project-level work allowance, not a second hourly-rate overhead.
3. The adopted recreation reference is rounded down to **EUR 70,000**, a **EUR 3,025** reduction.
4. The proposed seller asking reference is `EUR 70,000 × 30% = EUR 21,000`.
5. Indicative negotiation references are **EUR 16,800–26,250**, calculated as 80% and 125% of the asking reference.

The **30% factor is a seller-side negotiation choice** for the existing prototype and its remaining transfer conditions. It is not an observed market discount and is not supplied by WIPO, Knab or Upwork.

The engineer-month allocation estimates the professional work to reproduce the bounded implementation and evidence. It does not imply that the original author spent that time, that AI-assisted reproduction must cost this amount, or that a buyer could not use a cheaper substitute.

## Sensitivity and secondary model context

The role budget represents **560 assumed hours**. Applying the Knab mean uniformly gives `560 × EUR 94 × 1.15 = EUR 60,536`. An analyst low scenario of 420 hours at EUR 85/hour plus 15% gives **EUR 41,055**; 700 hours at EUR 137.50/hour plus 15% gives **EUR 110,688**, rounded. This range varies effort and rate; it is **not a statistical confidence interval** or a range of contractor quotations.

The existing site's market, income and strategic proxies and 25%/20%/20%/35% weights are retained for arithmetic consistency. These proxies all share the same recreation-cost anchor. They are correlated analytical scenarios, not independent comparable-transaction, DCF or royalty valuations. No observed MIPP IP sale, paying-user base or attributable recurring income is used.

The new MIPP prototype-to-developed-software figure is a **constant-cost maturity sensitivity** only. It is not a future asking price or a price for the pending v0.5 application.
